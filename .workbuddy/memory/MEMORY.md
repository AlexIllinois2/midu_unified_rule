# midu_unified_rule 项目记忆

## 引擎误读规律（2026-11-05 用户实测发现）

字节语音包（MultiTTS midu）底层有「三三变调 + 词尾轻声化」两步处理，rule 文件里没有 3+3 变调规则（只有 不 *2 / 一 yi2 的 PINYIN 条件规则）。导致：

- **三声字+子**（板子/底子/点子/椅子…）不修时全部误读为 `*2 *5`
- **三声字 AA 叠词**（姐姐/婶婶/奶奶/嫂嫂…）同样误读为 `*2 *5`

修复模式（词级 TEXT 规则，强制第二音节离开三声，底层变调即不触发）：
- X子：`底子	*3 *5	TEXT((底子))`
- 叠词：`姐姐	*3 *1	TEXT((姐姐))`（第二个字用一声化轻声，更贴近口语）
- 例外：`小伙子 xiao2 huo3 zi5` 是词内 3+3 的**正确**变调，需手动保住 xiao2

vendor 里只零星处理过 姥姥（重复两行）、本子 等，存在大量同规律缺口。

**已实测确认（2026-11-05）**：单字 char-list 规则 `子 *5 TEXT([...](子))` **救不了首字**（椅子在该列表里仍读 *2 *5）——变调发生在规则之前，必须用词级规则逐词修 `X子 *3 *5 TEXT((X子))`。已按此模式批量补入 70 条常用三声 X子 词（矮子…爪子，位于 嘴子 行之后）。

## 规则文件机制

- 条件类型：TEXT(正则上下文) / WORD_INSIDE(词内位置, -1=末位, 0=首位) / PINYIN / POS
- vendor 第47行：`子 *5 WORD_INSIDE(-1) !WORD_INSIDE(0)` 词尾子读轻声
- organizer 会按条件类型分组、组内重排序输出 unified_rule.txt（与 vendor 原始顺序不同）
- **ü 记法**：vendor 自己把 ü 写成 `v`（`血 xve4 TEXT((血)晕)`、`晕 yvn4`、`畜 xv4`、`菌 jvn1`、`炔 qve1`，共 33 行人工规则），所以 xue/jue/que/yue/yun/yuan 一律写 `xve/jve/qve/yve/yvn/yvan`，u 类（雨/于/浴）写 `yv3/yv2/yv4`。补丁里旧的 `xue1`(削)、`que4`(阙)、`yun4`(晕/运气)、`xuan2`(旋转) 是标准拼法，未必被引擎识别，暂未改；若哪天测出无效，统一换成 v 形式。

## 多音字通配 + 词级覆盖模式

- 补丁里 `血 xie3 TEXT((血))` 这类单字通配 = 定「口语默认读法」，书面语/专业词再用**上下文规则**覆盖，且优先写「单字 + 字符表」的紧凑形式（用户偏好，别铺开成一堆词级规则）：
  `血 xve4 TEXT((血)[液|压|糖|脂|型|…])` + `血 xve4 TEXT([鲜|热|浴|心|…](血))`
- 覆盖不到的再退回词级：`血液	xve4 ye4	TEXT((血液))`（只有 血晕 这类特例才需要）
- 同理可用于：累/种/长/背/假 等已有单字通配的字——缺哪个词补哪个，不必拆掉通配。
- 注意：xie3 通配行（拼音 xie3）排序时永远排在 xve4 上下文行前面——见下节「同 key 取首个命中」，这确实会遮蔽后面的规则。

## 同 key 规则「取首个命中」（已确认的关键机制）

同一触发字（key）有多条规则时，**按条件类型分组排队：PINYIN → WORD_INSIDE → TEXT → POS**。

- **WORD_INSIDE 命中 = 锁定**，后面的 TEXT 规则再也改不了这个字。这是所有「子/儿/个/吧」问题的总根源。
- **TEXT 组内部不按行序遮蔽**（2026-11-06 实测确认：血液、长辈、假期 全部正确，尽管 xie3 通配 / chang2 通配都排在具体上下文规则之前）——TEXT 之间可以互相覆盖（后写或最具体者生效）。
- 因此 TEXT 组内那些「通配在前、具体在后」的写法是安全的，不用重排。8 个 key（血/长/削/假/种/啦啦/便宜/棍儿）、26 条具体规则经实测无需处理。
- 实证：`子 *5 WORD_INSIDE(-1) !WORD_INSIDE(0)`（输出第 21 行）遮蔽了 vendor 第 1344-1362 行全部 `子 zi3/zi5 TEXT(...)`——所以「原子」读错**不只是**三三变调。全库审计（tmp/shadow_audit.mjs）共 **36 条此类死规则 / 7 个 key**：子 19、个 10、吧 2、儿 2、嘛/哦/呀 各 1，均已被词级规则覆盖。
- **唯一处方：换 key**。词级规则（key=整词，如 `原子	*2 *3`）或前字规则（key=子前那个字，如 `椅	*3	TEXT((椅)子)`）都能绕开。任何以被锁字本身为 key 的补救（char-list、`子 zi3 TEXT(...)`）全部无效。
- 反例：`一`（23 条）、`行`（17 条）、`了`（13 条）同 key 多规则能共存，因为它们的条件互斥；而 `了/调/咯/哎` 的宽规则带 `WORD_INSIDE(0)`（单字成词限定），属窄条件，不遮蔽。

## 「儿」类（同「子」的坑，但规模小得多）

CC-CEDICT 统计末字为「儿」的 2-4 字词条：**er2 全声 57 条 / r5 儿化 358 条 / er5 轻声 0 条**。
- 全声批（36 条词级）：`女儿 *3 *2`、`婴儿 *1 *2`、`孤儿`、`胎儿`、`新生儿`、`试管婴儿`…（人/科学类）
- 儿化批用引擎的儿化语法：`味儿	weir4 none5	TEXT((味儿))`、`老头儿	lao3 tour2 none5`（前音节加 r，儿本字写 `none5`）；补丁原有 14 条 + vendor 20 条 + 新增 25 条
- 坑：CC-CEDICT 的 ü 写作 `nu:3`，引擎不认；改写成 `nv3` / `nvr3` 有效（**已实测**：女孩儿 nv3 hair2、孙女儿 sun1 nvr3 读对，这是全库首次用 nv 写法）；「这会儿/那会儿」口语 zhèi/nèi，暂用标准音 zhe4/na4（vendor 有 `那 nei4 TEXT((那)天)` 证明引擎认 nei）；「媳妇儿」前字轻声要手工定。

## 无规则多音字：词典兜得住，别乱加（2026-11-06 实测）

抽测 130 个常见多音字，有 36 个在 unified_rule.txt 里**一条规则都没有**（还角落处缝斗恶供强散扇省吐屯尾鲜兴与扎粘钻径刨期帅贴铺裹曾腊喇宁壳弄模喂）。

**实测四个高危词全部正确**：处理 `*2 *3`（chǔ→chú 三三变调）、归还 `gui1 huan2`、参与 `*1 *4`、模样 `mu2 yang4`。

结论：
- 引擎词典/模型自带的多音字判断**相当可靠**，rule 文件只是补充少数个案。「无规则」≠「会读错」，不要为这类字批量补规则——加错了反而制造错误。
- 真正会错的是**词典没有收录的口语组合**：咽口水（咽默认 yān）、挑了挑眉头（挑默认 tiāo）、投子认输（子被词尾规则吃成轻声）。这类词汇表里查不到，只能靠听。
- 判断顺序：先看该字有没有规则 → 没有就用常见词实测一两个 → 确实错再补，不要凭"多音字"三个字就动手。
- **例外机制（重要）：派生词会丢失词根的读音**。词典管的是"词条"，管不了"词条 + 后缀/补语"的临时拼合：
  - `好事者` = 好事(hǎo shì, 好事情) + 者 → 默认 hǎo，实际 hào（2026-11-06 实测错）
  - `咽口水` = 咽喉(yān) + 口水 → 默认 yān，实际 yàn
  - `挑了挑眉头` = 挑(tiāo) + 补语 → 默认 tiāo，实际 tiǎo
  - `投子认输` = 投 + 子(词尾被 `子 *5` 吃成轻声) → 实际 zǐ
  所以「词典兜得住」的前提是**该组合本身是词典词条**；凡是「词根 + 后缀/补语/衬字」拼出来的，都可能在补。
- **连带陷阱：改字调值会留下前字的变调残影**。变调在规则之前执行，若原字被词典定为三声、规则事后改成四声，则它前面那个三声字早已被按 3+3 变成二声，而且没人改回来。
  - 实例：`好事者` 的「好」原来是 hǎo(3)，规则改成 hào(4) 后，「有」仍停在 yóu(2) → 读成 yóu hào shì zhě（2026-11-06 实测）。
  - 补法：给前字单独加规则，`有	*3	TEXT((有)好事者)`。前字不定时只能逐个补，或把整段写进词级规则。
  - 反过来也是收益：如果前字本来就该变调（打底子 dá dǐ zi），让引擎自己算即可，不要手写 `*2`。

## 上下文规则写法：结构匹配 > 字数窗口（2026-11-06 实测）

写「X 和 Y 之间可能隔字」的规则时，**不要用字数窗口**（`(挑).{0,6}眉`、`(挑).*眉`），要用**语法骨架**：

- 反例：`挑 tiao3 TEXT((挑).{0,6}眉)` 会把「他**挑**着担子，眉头紧锁」「**挑**水的时候皱着眉」里的挑也读成 tiǎo —— 动作描写和表情描写在小说里经常挨着，误伤必然发生。
- 正例：`挑 tiao3 TEXT((挑)[了起][挑下]?眉)` + `挑 tiao3 TEXT((挑)了一下?眉)` —— 中间只允许 了/起/挑/下/一 这几个补语标记。「挑着/挑水/挑担/挑选/挑食」的后续字（着/水/担/选/食）不在集合里，结构上天然挡住。**已实测通过**。
- 引擎正则能力（实测支持，可放心用）：`(?:...)` 非捕获组、`[^一-龥]` 否定类、`^` `$`、`?`、`{n,m}`；匹配是 **find 语义**（可部分匹配，`.*` 常作前缀用）。

## 多音字无通配时的处理（挑 为例）

「挑」在 vendor/补丁里**没有任何 WORD_INSIDE 或单字通配**，读音完全由词典给（tiāo），所以所有 tiǎo 语境都错，只能逐片补上下文规则：
- 修辞/动作类：`(挑)[明|灯|拨|衅|战|逗|唆|弄|起|破|帘|动|头]`、`(挑)眉`、`(挑)了挑`、`挑了(挑)`
- 不动（确为 tiāo）：挑选 挑剔 挑食 挑夫 挑水 挑担 挑刺 挑毛病 挑三拣四 挑肥拣瘦 挑嘴 —— 「挑刺/挑毛病」语感像 tiǎo，按《现汉》实际是 tiāo，别被骗。

## 两读多音字的自动判定：三层信号 + 词典审计闭环（长 为例，2026-11-06）

对于「某字两种读音都常见」的情况（长 cháng/zhǎng、血 xiě/xuè、差 chā/chà…），**不要靠词表逐个补**，用三层信号，再用词典做反向审计：

1. **后接字表**（覆盖词典内词条）。做法：把 CC-CEDICT 里该字开头的全部词条按读音分组，看「后一个字」能否唯一判定。长的实测：143 条词条里只有 毛/牙/虫 三字两读，其余全可判 → 一条字符表覆盖 100% 词典词条。
2. **前置虚词/动词**（覆盖词典外的生造组合，这层最关键）。`(?:忘|没|白|才|刚|正在|正)(?:了)?(长)` 能救「忘了长屁股」「没长牙」「白长了」这类词典根本没有的短语。注意**排除「不」「要」**：`不长`（时间不长）、`要长`（要长一点）都是 cháng 的高频用法。
3. **后接补语**：`(长)着[^呢]`（长着一颗痣 ✓ / 长着呢 ✗）、`(长)(?:起来|下去)`、`(长)不[大上了]`（长不大 ✓，同时避开「长不长」）。

**审计闭环（必做）**：写完后用词典逐条回判，统计「误伤」（本该甲读被改成乙）和「漏判」。`tmp/audit_chang.mjs` 是模板，改字即可复用。长的结果：误伤 0、漏判 5（全是词典本身两读的 2 字词）。**误伤必须是 0 才算过关**，漏判可以留。

**改造老规则时要先查 bug**：长的原字符表里有 `成`/`出` 两项，导致 长城→zhǎng chéng、长出一口气→zhǎng chū。加了否定类和特例（`(长)成(?:[^城]|$)`、`(长)出了?一口气` 归 cháng）才修掉。凡是往字符表里塞「高频但构词力强」的字（成、出、大、上），都要检查它是否也参与另一读的高频词。

## 派生词丢读音 / 变调残影（今日多条规则的总规律）

- 词典能读对的前提是**该组合本身是词条**；「词根 + 后缀/补语/衬字」拼出来的会丢读音：好事+者→好事者(hào)、咽喉+口水→咽口水(yàn)、挑+了挑→tiǎo、投+子→投子(zǐ)。
- 用规则改某字调值后，**它前面那个三声字已经被底层变调过了**：`好事者 *4 *4 *3` 改不到「有」（词典 有3+好3 → 有被变形成 yóu）。必须补 `有 *3 TEXT((有)好事者)` 把它扳回来。反向也有：`打底子` 不用手写 *2，引擎自己算对。

## 两类「一个字两读、且两边前置字都开放」的字：只能默认+结构补（观 为例）

长的两读可以靠后接字表全覆盖；但**观（guān/guàn）不能**，因为两个集合都开放：
- guān 作动词，前字开放：静观其变、纵观全局、反观、远观、俯瞰、默观、笑观、坐观
- guān 作名词，前字开放：乐观、悲观、客观、宏观、微观、壮观、奇观、景观、直观、外观、三观、世界观、人生观
- guàn（道教庙宇），前字更开放：任意观名（清虚观、玄都观、上清观…词典全不收）

所以**不要试图反向设默认 guàn**，正确姿势是「默认 guān（交给词典）+ 用庙宇特有的语法位置补 guàn」：
1. **方位/建筑词**：观+里/中/外/内/前/门/后 —— 动词义的观后面不会跟方位词。但必须加**前字排除类** `[^参围旁直宏微主客乐悲景奇壮改]`，否则 参观中、围观中、参观内容、观后感 全被误伤。
2. **句首/标点后**单独一条 `(?:[^一-龥]|^)`，否则「观中一片寂静」开头漏掉。
3. **量词**：这座观 / 有一座观（`[一二两…几这那每]座(观)`；不能用裸 `座(观)`，会被「讲座观察」误伤）。
4. **同类复合**：道观/宫观/寺观/庵观/祠观。

教训：写「X+方位词」类规则时，先列出 **X 作动词时的高频前搭配**做成排除类，这是误伤的唯一来源。每次写完都跑词典回判，误伤必须为 0。

## 厂商 `6` 声调标记 = 三声变调保护（推断，2026-11-06）

vendor 里有一批 `x6` 写法：`醒 xing6 TEXT((醒)醒)`、`缓 huan6`、`两 liang6`、`莞 wan6 TEXT(相顾(莞)尔)`、`掸 dan6 TEXT((掸)帚)`、`辗 zhan6 TEXT((辗)转)`、`稽 qi6 TEXT((稽)首)`、`老 lao6 TEXT((老)奶奶)`、`靡 mi6`、`倥 kong6`、`济 ji6`、`嘎 ga6`、`尺 che6 TEXT(工(尺)谱)`。

共同点：**全是三声字，且原调处于「三声+三声」或「三声+轻声」环境**（工尺谱 gōng chě pǔ，尺后接三声谱）。推断 `6` 是「保持三声原调、不参与三三变调」的引擎标记（不是合法声调，organizer 原样透传）。

用法：给这类位置补规则时，**照抄厂商的 6**，不要自作聪明改成 3；除非该字在词尾且后面不接三声（如 `酊 ding3`、`撮 zuo3`、`埔 pu3`、`若 re3` 厂商就是写 3）。

## 厂商「只写长词、裸词掉默认读音」（2026-11-06 婀娜案例）

厂商对多音字往往**只把读音写进带后缀的长词规则**，裸词没有任何规则，于是回落词典默认读音：

| 裸词 | 厂商只写了 | 引擎裸读 |
|---|---|---|
| 婀娜 | `娜 nuo2 TEXT(婀(娜)多姿)` | e1 na4 |
| 刹那 | `刹 cha4 TEXT(一(刹)那)` | sha1 na4 |
| 酩酊 | `酊 ding3 TEXT(酩(酊)大醉)` | ding1 |
| 一撮 | `撮 zuo3 TEXT(一(撮)毛)` | cuo1 |
| 黄埔 | `埔 pu3 TEXT(黄(埔)军校)` | bu4 |
| 兰若 | `若 re3 TEXT(兰(若)寺)` | ruo4 |
| 虎跑 | `跑 pao2 TEXT(虎(跑)泉)` | pao3 |
| 中牟 | `牟 mu4 TEXT(中(牟)县)` | mou2 |
| 图们 | `们 men2 TEXT(.*图(们)江)` | men5 |
| 畹町 | `町 ding1 TEXT(畹(町)镇)` | ting1 |
| 工尺 | `尺 che6 TEXT(工(尺)谱)` | chi3 |

修法：补一条更短的前缀规则即可，TEXT 组内长词仍优先、同拼音不冲突：
`刹 cha4 TEXT((刹)那)`、`埔 pu3 TEXT(黄(埔))`、`尺 che6 TEXT(工(尺))`…

**判定逻辑**：厂商肯为「词+后缀」写规则，说明引擎在该词里就读错 → 裸词同样错。
**但不可无限外推**：扫描器 `tmp/scan_bare_word.mjs` 扫出 42 条同结构候选，多数是引擎词典本就正确的轻声词（学生/身上/弟兄），或裸词本身有歧义（同行 tóng xíng/háng、一行、大伯 dà bó），一律不能补。只补「多音字在固定词/专名里选错读音」这一类。

**注意**：补丁里写**独立注释行**（`# xxx`）会被 organizer 当成一条规则输出到 unified_rule.txt 顶部（分组 OTHER），只能用**行尾注释**。

### 裸词补丁的最大坑：假前搭配制造子串误伤（2026-11-06 实测）

TEXT 是 **find 语义**，写 `跑 pao2 TEXT(虎(跑))` 以为在管地名「虎跑泉」，结果「那只**老虎跑**山里去了」里的「虎跑」两个相邻字也命中 → 老虎跑 → lǎo hǔ páo（错，应 pǎo）。
裸词越短越危险。**每加一条裸词规则，必须先列出该词的高频「假前搭配 / 假后搭配」**：

| 规则 | 被误伤的句子 | 收窄办法 |
|---|---|---|
| `虎(跑)` | 老虎跑山里去了 | 要求前字是介词/句首/标点 `(?:[去在到往从至离住游逛]|^|[^一-龥])虎(跑)`，或后接专名尾字 `虎(跑)[泉寺路公梦]` |
| `兰(若)` | 木**兰若**是知道 / 木兰若干年 | 前置排除木：`(?:^|[^木])兰(若)` |
| `工(尺)` | 施**工尺**寸 | 后接排除：`工(尺)(?:谱|[^寸码]|$)` |
| `中(牟)` | 途**中牟**取暴利 | 后接排除：`中(牟)(?:县|[^取利])` |
| `一(撮)` | 统**一撮**合 | 后接排除：`一(?:小)?(撮)(?:[^合]|$)` |

前置排除（`[^木]`）比后接排除更省事，但只在该词的前搭配集中时才可用。回归测试模板：`tmp/verify_bare_word.mjs`（29 条正反例，全通过才算过关）。
