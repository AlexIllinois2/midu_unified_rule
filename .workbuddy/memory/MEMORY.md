# midu_unified_rule 项目记忆

## 引擎误读规律（2026-11-05 用户实测发现）

字节语音包（MultiTTS midu）底层有「三三变调 + 词尾轻声化」两步处理，rule 文件里没有 3+3 变调规则（只有 不 *2 / 一 yi2 的 PINYIN 条件规则）。导致：

- **三声字+子**（板子/底子/点子/椅子…）不修时全部误读为 `*2 *5`
- **三声字 AA 叠词**（姐姐/婶婶/奶奶/嫂嫂…）同样误读为 `*2 *5`

修复模式（词级 TEXT 规则，强制第二音节离开三声，底层变调即不触发）：
- X子：`底子	*3 *5	TEXT((底子))`
- 叠词：`姐姐	*3 *1	TEXT((姐姐))`（第二个字用一声化轻声，更贴近口语）
- 例外：`小伙子 xiao2 huo3 zi5` 是词内 3+3 的**正确**变调，需手动保住 xiao2

vendor 里只零星处理过 姥姥（重复两行）、本子 等，存在大量同规律缺口。

**已实测确认（2026-11-05）**：单字 char-list 规则 `子 *5 TEXT([...](子))` **救不了首字**（椅子在该列表里仍读 *2 *5）——变调发生在规则之前，必须用词级规则逐词修 `X子 *3 *5 TEXT((X子))`。已按此模式批量补入 70 条常用三声 X子 词（矮子…爪子，位于 嘴子 行之后）。

## 规则文件机制

- 条件类型：TEXT(正则上下文) / WORD_INSIDE(词内位置, -1=末位, 0=首位) / PINYIN / POS
- vendor 第47行：`子 *5 WORD_INSIDE(-1) !WORD_INSIDE(0)` 词尾子读轻声
- organizer 会按条件类型分组、组内重排序输出 unified_rule.txt（与 vendor 原始顺序不同）
